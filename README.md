# Программа форматирования текста

Реализация по внешней и внутренней спецификациям. Считывает текст из файла,
разбивает его на слова, собирает строки нужной ширины и выравнивает их по
ширине методом равномерного распределения пробелов.

## Структура

```
text_formatter/
├── include/
│   └── text_formatter.h      # ErrorCode, FormatError, класс TextFormatter:
│                             # parseWords, buildLines, justifyLine, getOutputLines
├── src/
│   ├── main.cpp              # точка входа (app)
│   ├── text_formatter.cpp
│   └── CMakeLists.txt        # цели: core (статическая библиотека), app
├── tests/
│   ├── tests.cpp             # модульные тесты (GoogleTest)
│   ├── run_tests.sh          # интеграционные батарейные тесты (macOS/Linux)
│   ├── run_tests.bat         # интеграционные батарейные тесты (Windows)
│   └── CMakeLists.txt        # цель: unit_tests
├── docs/
│   └── Doxyfile.in           # шаблон конфигурации Doxygen
└── CMakeLists.txt            # корневой CMake (C++20, опция BUILD_DOCS)
```

## Требования

| Инструмент | Минимальная версия |
|---|---|
| CMake | 3.20 |
| Компилятор | C++20 (GCC 10+, Clang 13+, MSVC 2019+) |
| Doxygen | любая *(опционально)* |

Доступ к интернету во время сборки нужен только при первом запуске — CMake
автоматически скачает GoogleTest через `FetchContent`.

## Сборка

```bash
cmake -S . -B build
cmake --build build
```

Для Release-сборки:

```bash
cmake -S . -B build -DCMAKE_BUILD_TYPE=Release
cmake --build build
```

Отключить генерацию документации:

```bash
cmake -S . -B build -DBUILD_DOCS=OFF
```

## Запуск

```bash
./build/src/app <входной_файл> <ширина> <выходной_файл>
```

Коды возврата: `0` — успех, `1` — ошибка (неверные аргументы, некорректный
файл или невозможность создать выходной файл).

**Формат входного файла** — произвольный текст на русском или латинском языке,
строки разделены переносами. Допустимые символы: буквы (ASCII и кириллица),
цифры, пробелы, табуляции, разрешённые знаки препинания (`. , ! ? ; : - ( ) [ ] { } " ' / \ + = < >`).

**Параметр ширины** — целое число от 40 до 120 (включительно).

Пример входного файла:

```
Это простой пример текста для форматирования.
Программа выровняет его по заданной ширине.
```

Пример вызова:

```bash
./build/src/app input.txt 60 output.txt
```

## Ограничения

| Параметр | Ограничение |
|---|---|
| Ширина строки | 40–120 символов |
| Длина строки входного файла | не более 1024 символов |
| Количество строк в результате | не более 1000 |

## Модульные тесты (GoogleTest)

```bash
cmake --build build
ctest --test-dir build --output-on-failure
```

Или напрямую:

```bash
./build/tests/unit_tests
```

## Интеграционные тесты

```bash
# macOS / Linux
chmod +x tests/run_tests.sh
cmake --build build
./tests/run_tests.sh

# Windows
cmake --build build
tests\run_tests.bat

# Windows — указать путь к исполняемому файлу явно
tests\run_tests.bat build\src\app.exe
```

Скрипт запускает сценарии, охватывающие: корректное форматирование,
все виды ошибок входных данных, граничные случаи ширины, недопустимые символы,
пустой файл, слишком длинные строки и слова.

## Документация

Если Doxygen установлен, цель `docs` сгенерирует HTML в `build/html/`:

```bash
cmake --build build --target docs
```

## Соответствие критериям

* **Универсальность.** `TextFormatter` корректно обрабатывает кириллицу и ASCII,
  знаки препинания, примыкающие к словам и стоящие отдельно, множественные
  пробелы и пустые строки. Выравнивание работает для строк с одним словом
  и для последних строк абзаца.
* **Надёжность.** `parseWords` возвращает `FormatError` с кодом ошибки, номером
  строки и позицией символа. Программа никогда не завершается аварийно на
  некорректных данных.
* **Структурность.** Алгоритм разбит на функции:
  `parseWords`, `buildLines`, `justifyLine`, `getOutputLines`,
  а также вспомогательные утилиты для UTF-8: `utf8Len`, `utf8Codepoints`,
  `isAllowedCodepoint`, `isPunctToken`.
* **Читабельность.** Имена функций и переменных полные и осмысленные.
  Комментарии в стиле Doxygen, единый стиль форматирования.
* **Покрытие тестами.** Модульные тесты GoogleTest для всех методов класса
  `TextFormatter`, интеграционные батарейные тесты через `run_tests.sh` / `run_tests.bat`
  для всей программы целиком.
